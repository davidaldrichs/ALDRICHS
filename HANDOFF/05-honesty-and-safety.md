# 05 · 诚实与安全底线（接手必读，必须继续守）

这个项目从头到尾守着两条底线。它们不是可选的，是这个工具能被信任的根本。下一个 agent 必须继续守。

## 底线一：不编造算法 / 数据去糊弄"能用"

- **没有就说没有**。MINI/宝马/JLR 的解锁开源里没有、新款 RSA 从原理上拿不到——就如实标 `unsupported`，演示里**如实失败**（报"需要逆向"），绝不塞一个假算法让它"看起来能解锁"。
- 具体做法：这几个品牌的演示 ECU 用一个**故意不在算法库里**的 secret（如 bmw.ts 的 `(b*7+0x11)&0xff`、jlr.ts 的 `(b+7)&0xff`），这样 `security-access` 引擎试一圈后如实返回 `unlocked:false, reason:"...需要逆向..."`。
  - ⚠️ 坑：别让这个 secret 等于 `seedkey.ts` 里任何通用算法（否则演示会"假成功"）。宝马那次就踩了——`(b^0x5a)` 正好等于通用的 `xor-5a`，导致解锁假成功，后来改成 `(b*7+0x11)`。加新"无解锁"品牌时注意避开通用算法。
- **真实算法必须可溯源**：大众 SA2(移植自 bri3d/sa2_seed_key MIT，有官方测试向量验证)、奔驰 Daimler(移植自 jglim/UnlockECU MIT，自洽验证但**无官方向量，未实车校准**，代码和文档都标了)。移植别人的开源算法要**标来源和许可**，并说清验证程度。
- **GPL 代码不抄进来**（如 PSA 的 GPL 算法会传染本项目许可，没采用，只在文档记一笔）。
- **不夸大状态**。真车相关的任何"完成"都要带"未实车验证 + 需车型数据"的前提。

## 底线二：改 ECU 有护栏（不做危险的自动化）

改 ECU 可能爆震拉缸、ECU 变砖、行车出事、排放违规。所有改写功能都带护栏，已经建好，**别拆**：

1. **范围钳制**：所有可改参数都有 min/max，写入前强制钳制（`tuning.ts` normalizeValue、`map-def.ts` writeMap 双重钳制到物理范围+原始位宽）。
2. **AI 只当参谋不当手**：AI 只在有范围的参数内建议，给的值一律过钳制，**人工逐项确认**才生效，**绝不自动刷写**。AI 碰不到没有定义/没有范围的原始字节。
3. **保留原厂备份**：恢复/刷写前自动备份当前程序（flash-runner backupFirst）。
4. **读回校验**：写完读回逐字节比对（flash-runner verifyAfterWrite）。
5. **刷前安全检查**：电压过低拒绝刷写（防断电变砖）。
6. **读写时禁止断开/抢通讯**（main.ts state.flashing 守卫）。
7. **防刷错车**：.mrbk 备份带 VIN，恢复前 checkRestore 校验是不是这辆车、ECU 型号对不对、文件没损坏。

## 明确不做的

- **不做"删排放设备后屏蔽排放监控故障码"**——那是法律意义上的失效装置。故障码隐藏只做**软件显示层**（不写 ECU、不熄故障灯，界面写明）。在 ECU 里永久关故障码属于改程序，而专门为过年检/删三元 EGR DPF 后遮码，拒绝。
- **不做通用的 security access 暴力破解器**——那是偷车/非法改装手法。现有的"一键解锁"是**试已知的公开算法**且有尝试上限，和暴力穷举钥匙空间是两回事。
- 相关警示在 UI 和文档里都写着：改动力程序影响排放合规/年检/质保，务必台架或测功机验证。

## 一句话

能做的就真做、做扎实、带护栏；做不到的就如实说做不到。这比"看起来功能多"重要得多。

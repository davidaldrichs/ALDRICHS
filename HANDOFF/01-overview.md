# 01 · 这个工具是什么

## 背景（用户的原始需求演变）

用户最初要"手机刷 MINI R 底盘(一代/二代)的程序"。随着对话推进，目标扩大成一个**近乎全平台的刷写/调校工具**，MINI 只是第一个，后面陆续加了奔驰、宝马、捷豹路虎、大众集团，并要求：
- 电脑(Windows) exe 版
- 读取原厂程序 / 备份
- 解锁(seed/key)
- 调马力 / 改程序
- 接入 AI 调程序
- 读 log 数据、能按条件自动跑 log
- 导入 map 定义(XDF)来真正改增压/点火等

## 现在能干什么（三档，务必分清）

### ✅ 现在就有、真能用
- **演示模式**：不接车，所有功能都能完整走通、点得通（每个品牌一个模拟 ECU）。
- **诊断**（接 ELM327 适配器即可在真车用，走标准 OBD-II）：读/清故障码（含中文说明）、实时数据仪表、VIN/标定号/CVN、支持的 PID 探测。
- **数据记录（Log）**：勾通道→记录→导出 CSV；**自动触发**（如节气门>90% 自动开始、到时长/松开自动停）；**AI 生成记录方案**（一句话→选通道+触发）。走标准 OBD，真车可用。
- **故障码软件端隐藏**（仅本地显示层，不写 ECU，界面写明）。

### 🟡 软件/框架做好了，上真车还需要"车型数据"
- **解锁(seed/key)**：引擎完整(UDS/KWP 握手、防锁定、自动试算法)。真实算法里 **大众 SA2 已用官方测试向量验证**、**奔驰 Daimler 已移植**(自洽验证，无官方向量)。真车要那台 ECU 的 SA2 脚本(大众)或 K 私钥(奔驰)。
- **读取/备份/恢复**：**真实 UDS 协议**(10/27/34/36/37/35/31/11)，演示跑通，真车要内存地址等参数。
- **Map 调校(XDF)**：真能解析 XDF、从 ROM 读 map、改(标量/整表缩放)、范围钳制、导出改后 ROM。要匹配的 XDF + ROM。
- **AI 调校顾问**：真能调用 OpenAI 兼容 / Anthropic API，在"有范围的参数"内给建议，强制钳制、人工确认、不自动刷。

### ❌ 开源做不到 / 没做
- **MINI / 宝马 的解锁和刷写**：私有协议，新款(MG1/MD1)是 RSA 签名，私钥锁在 ECU bootloader，外部推不出。开源无算法。→ 这两个品牌解锁标 `unsupported`，演示如实报"需逆向"。MINI 备份只能走 boot 模式/台架(绕过 seed/key)。
- **捷豹路虎**：开源无 seed/key，同样标 `unsupported`。
- **真正的"马力 map"没有内置**：需要用户自己导入对应 ECU 的 XDF 定义。
- **没在任何真车上实测过**。
